# Russian meetings and summaries

New meeting setups default to Russian. Saved language choices remain unchanged. The upstream Parakeet v3 final meeting backend already accepts Russian; Pichi adds buffered Russian live captions using Parakeet v3 on Apple Silicon, or the selected GigaAM model on either Mac architecture. English captions keep their existing streaming path. GigaAM live and final processing share a pinned export identity; without an installed speaker model, the final transcript keeps source tracks without claiming individual speaker identities.

The meeting Summary tab uses a Pichi provider based on the public `LLMClient`, independent of the private Fluid Intelligence runtime. Its default destination is Ollama on `http://127.0.0.1:11434/v1`, with `qwen3.5:4b` selected. Ollama and model weights must be installed separately. Refresh models to discover installed IDs, or enter a model served by LM Studio's compatible local API. `qwen3.5:2b` is an alternative when memory is limited. Actual memory and speed depend on the server's context configuration and require measurement on the target Mac.

For the standard localhost Ollama endpoint, Pichi uses the native Chat API with a fixed 8192-token context, a 3000-token output budget, temperature zero, thinking disabled, and a constrained JSON schema. Each request uses `keep_alive: 0` to release the model before ASR resumes. This avoids Ollama allocating the model's much larger default context and does not change global server settings or create another copy of its weights. Other endpoints retain the existing OpenAI-compatible transport. The output limit or invalid citations cause rejection, never acceptance of a partial summary.

Russian is the default summary language. English and the transcript's language are selectable independently of transcription. The optional Configured AI provider mode reuses an OpenAI-compatible provider selected in AI Enhancement settings. Its endpoint and model are displayed before generation. Remote endpoints require HTTPS and existing credentials; there is no automatic cloud fallback. A generation request sends transcript text, not audio. Summary transport and model discovery use an ephemeral session and reject HTTP redirects, so a localhost endpoint cannot redirect the transcript to a remote destination.

Every recap, decision, task and open question includes source segment IDs and exact transcript excerpts. Unknown IDs, invented quotations, and owners or dates absent from cited source speech or speaker labels cause rejection. This validates attribution and citations, not the semantic truth of every generated claim. Review the Sources disclosures before acting on a task or decision.

During generation, citations use compact numeric references into an immutable request-local source catalog. The application prepares literal excerpts before inference and resolves only known references back to the existing UUID/quote document format before strict validation. The model cannot rewrite a quote through this path. Repeated source passages retain their original order. Reduction uses verified recap evidence, and reconciliation references only the supplied later changes or answers. Each catalog has at most 128 entries; encoded request input and schema each have a 64 KB limit. Native Ollama constrains reference choices through its existing structured-output API. Other compatible endpoints receive the same reference instructions through the existing transport.

A malformed result or failed citation/attribution check permits one regeneration with a safe categorical explanation and the same immutable input. The rejected private output is not appended to the next prompt. A second invalid result remains rejected; cancellation and transport errors never start this validation repair. Memory, output and model-residency limits remain unchanged. The saved artifact continues to contain canonical segment IDs and quotes, never request-local indices.

Long transcripts are processed sequentially in bounded chunks. A separate reduction stage condenses the recap; the decisions and task ledger remains complete. Explicit later cancellations or replacements are extracted and reconciled against the ledger. An earlier entry is retained as superseded, with the later correction's source quotation. Reconciliation cannot rewrite its original text, owner or date, remove it, or use an earlier event to supersede it. Transcript gaps appear as a warning. Provisional turns and probable echoes are excluded. Corrections, speaker changes, language changes, gaps, and summary model changes invalidate saved results.

Questions are reconciled against definite later answers in the same bounded process. A resolved question keeps its original wording and question source, adds the verified later answer quotation, and displays Answered later instead of remaining open. Earlier answers, tentative suggestions and unrelated facts cannot close a later question. Original owners and dates are never rewritten.

Identical task, decision and correction wording from distinct source occurrences is retained. A task cancelled early and reinstated later remains active until a cancellation after its reinstatement. Summary generation runs inside the existing ASR model-residency scope, suspending speech, private AI and dictionary resources before LLM inference and restoring eligible residents after success, failure or cancellation.

The saved artifact is `pichi-meeting-summary.json` inside the existing session directory. It stores the transcript fingerprint, configuration identity, generation time and structured result. It contains no API credentials. Generation errors and cancellation do not replace or delete the transcript or audio. Existing upstream postprocessing artifacts remain compatible.

## Verification

`PichiMeetingSummaryTests` covers Russian evidence, invented citations/owners/dates, long turns, chunk reduction, cancellation, endpoint policy and invalidation. The suite is offline by default. For a real local inference check, run `testLiveRussianSummaryWithOllamaWhenEnabled` with `PICHI_MEETING_SUMMARY_LIVE=1` in the test process environment, after installing `qwen3.5:4b`. The fixture is synthetic and contains no personal audio or meeting information.

`testLiveSavedSessionSummaryWhenExplicitlyEnabled` accepts an explicitly authorized saved session through `PICHI_MEETING_SUMMARY_LIVE_SESSION_PATH`. It runs only against localhost and checks the completed result and unchanged transcript fingerprint. Keep this path and all private inputs in ignored local storage; the test does not modify the saved meeting.

Only launch the test host after the Pichi bundle, storage and Keychain identity changes are present. Compilation alone does not verify audio capture, local model availability, or performance on Intel.
