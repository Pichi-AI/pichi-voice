# Security policy

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/Pichi-AI/pichi-voice/security/advisories/new) for suspected security vulnerabilities in Pichi Voice. Please avoid public issues, pull requests or discussions containing exploit details or private data before the report has been assessed.

Include the affected app version or source revision, platform, expected security boundary, observed impact and minimal reproduction steps. Prefer synthetic examples. Do not attach private recordings, transcripts, voice profiles, credentials, verification codes or unredacted logs. If a credential has already been exposed, revoke or rotate it through its provider.

If GitHub reporting is unavailable, contact [hello@pichi.ai](mailto:hello@pichi.ai) with a brief description and ask how to share sensitive details. Do not email secrets or private recordings.

## Supported releases and testing

Security fixes target the latest stable Pichi Voice release and current `main`. Reports about prerelease or older versions are welcome; a maintainer may request reproduction on the current version. Older releases do not have a separate security maintenance commitment.

Test only systems and data you are authorized to use. A vulnerability report does not grant permission to access other people's recordings, accounts or services. Coordinate disclosure with the maintainer so a fix can be prepared before technical details are published.

For ordinary bugs, installation help and feature requests, use [Issues](https://github.com/Pichi-AI/pichi-voice/issues/new/choose) and [Support](SUPPORT.md).

## Сообщить об уязвимости

Отправьте [приватный отчёт в GitHub](https://github.com/Pichi-AI/pichi-voice/security/advisories/new). Укажите версию, устройство, шаги воспроизведения и возможные последствия. Используйте синтетический пример, без личных записей, расшифровок, ключей и кодов подтверждения. Не публикуйте детали уязвимости в обычном issue до согласования раскрытия.
